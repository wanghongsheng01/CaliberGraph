\section{Experimental Setup}\label{sec:setup}

\textbf{Benchmark and systems.} We use the 1,534 questions of the BIRD development set (2024-06-27 revision)~\cite{li2023bird}, which span eleven SQLite databases with 3--13 tables. Predictions come from the ten systems whose BIRD outputs were released with SpotIt+~\cite{tremante2026spotitplus}: Alpha-SQL~\cite{li2025alphasql}, CHESS~\cite{talaei2024chess}, CSC-SQL-7B/32B~\cite{sheng2025cscsql}, two GenaSQL submissions~\cite{donder2025genasql}, GSR (an anonymous entry listed in~\cite{tremante2026spotitplus}), OmniSQL-32B~\cite{li2025omnisql}, RSL-SQL~\cite{cao2024rslsql} and SLM-SQL~\cite{sheng2025slmsql}. These systems cover multi-agent pipelines, fine-tuned 7B--32B models and self-consistency. BIRD is the only Text-to-SQL benchmark for which verifier outputs on many systems have been released. This lets us compare all tool families on identical inputs. In addition, its databases are large real instances (3.9\,M rows), which tier $\mathcal A_R$ needs. We recomputed the released EX labels on the official databases. They agree on 15,339 of 15,340 pairs; the exception depends on the current date. The held-out schemas are \texttt{formula\_1}, \texttt{superhero} and \texttt{toxicology}. The development set has 349 questions and the test set has 1,174, i.e., 11,740 test (system, question) pairs. Of these, \V{nExc} are EX-correct, with 6,456 distinct predictions, and 3,745 are EX-incorrect.

\textbf{Baselines.} The baselines cover the main families of approaches that judge a prediction beyond EX. Each family has a strong public representative for SQLite and BIRD:
\begin{itemize}
\item \emph{Random fuzzing} follows the style of test-suite accuracy~\cite{zhong2020testsuite}. It generates 1--5 random rows per referenced table, with values drawn from both queries' literals, observed value samples, type-faithful values and \texttt{NULL}. Keys come from a three-value domain so that joins occur, and foreign and primary keys are repaired. Random fuzzing shares CaliberGraph's value coercion and certifier, but it has no join graph, anchors or isolation.
\item \emph{ParSEval}~\cite{chen2025parseval} performs coverage-driven symbolic generation; we use commit \texttt{88cfe245} with Z3~\cite{demoura2008z3} 4.16.0. ParSEval-L1 keeps its generator but accepts only certified databases, restarts with new seeds until the budget is spent, and receives the same observed format samples. Its unmodified \texttt{disprove} routine is reported as ParSEval (official). ParSEval's solver exceeded the budget and was stopped on 732 of the 6,456 distinct pairs.
\item \emph{SpotIt}~\cite{klopfenstein2026spotit} and \emph{SpotIt+}~\cite{tremante2026spotitplus} perform bounded verification without and with LLM-validated mined constraints, respectively. We use their released outputs and also re-run SpotIt under our budget (Section~\ref{sec:main}).
\end{itemize}
\emph{Excluded tools.} Provers such as SQLSolver~\cite{ding2023sqlsolver} and QED~\cite{wang2024qed} establish equivalence and return no counterexample database. VeriEQL~\cite{he2024verieql} is represented by SpotIt, which builds on it and reports BIRD results. XData~\cite{chandra2015xdata} and EvoSQL~\cite{castelein2018evosql} generate tests for one query or a mutant space rather than for a given pair. LLM judges~\cite{kim2025flex} produce no checkable evidence.

For the second freeze, \emph{random fuzzing-R} draws 1--5 real rows per referenced table from $D_0$ or template rows. It re-draws referenced columns from literals, observed values and \texttt{NULL}, and closes the result under foreign keys and total participation with real rows. \emph{ParSEval-R} gives ParSEval a value provider that returns observed values first. Because its solver still introduces unobserved values, it is a weak baseline at this tier, and we do not claim a fair comparison with symbolic generation at $\mathcal A_R$. Both baselines receive the same read access to $D_0$, profile, repair and certifier-in-the-loop acceptance at $\mathcal A_R$ as CaliberGraph-R.

\textbf{Budgets and platform.} All self-run tools get 5\,s of wall-clock time per distinct pair on one core, with two workers on a 2-core VM with 7\,GB of memory. A 10\,s budget is evaluated on a random subsample of \V{nSub} distinct pairs, which is also used for ablations. ParSEval-R certified none of 600 development pairs, so it was run on this subsample only, a decision made before the second test run. CaliberGraph is implemented in Python 3.13 with SQLGlot~\cite{sqlglot} and SQLite 3.45~\cite{sqlite}. The artifact repository contains the code, splits, raw outputs, witnesses, certifier reports, annotations and pre-registrations.
