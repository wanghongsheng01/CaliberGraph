# 07 第二次冻结方案：数据画像现实性层级 R 与 CaliberGraph-R（预注册）

起草时间：2026-10-14（UTC+8）。**本方案在任何 R 层方法于测试集上运行之前写定。** 动机见 06 号文档：第一次冻结版（v4）的测试集见证经盲标归因后，40–70% 只在现实中不会出现的数据上成立，所有方法都是如此。

## 1. 现实性层级 R（数据画像约束）

从官方 BIRD 库（用户提供）用标准数据画像查询自动挖掘，脚本为 `src_r/mine_profile.py`，结果写入 `data/official/profile_R.json`。见证必须在 L1f 的基础上，对其中**所有**表、所有列同时满足以下约束。

**单值约束**
- 只有在官方列中出现过 NULL 的列才允许 NULL。
- 数值必须落在观测范围内；官方全为整数的列必须是整数。
- 文本取值：观测到的不同值不超过 5,000 个的列，取值必须是观测值之一；其余列需满足三点：词形属于观测词形，大小写风格属于观测风格，首尾无空白（官方数据中本来就有的除外）。
- 时间类文本必须落在观测范围内。
- 主键和外键列（键列）允许新标识：数值键要求类型与整数性一致，文本键要求词形一致。

**唯一列组合（UCC）**
- 单列：所有列都检查。
- 两列：只在外键列、主键成员列或离散列（不同值不超过行数一半）之间挖掘。
- 要求表至少有 20 行。

**包含依赖（IND）**
- 未声明的外键：同名列取值包含于对方表的唯一列，泛名（id、name、type 等）除外。
- 完全参与：父表每一行都至少有一个子行。字典表父表除外。
- 对称关系与无自环：同一表中两列外键指向同一列时检查。

**字典表**：同时满足以下三点的表，见证中只能出现官方原行。
- 行数不超过 200；
- 列数不超过 3；
- 被外键引用。

**年份—日期一致**：名为 year 的整数列，若在官方数据中与同表某日期列的年份恒等，则见证中也必须相等。

对 R 层，我们也计算两个复合层级：
- R = L1f + 上述约束；
- R2 = L2 + 上述约束。

## 2. 方法

### CaliberGraph-R（代码在 `src_r/`）
保留 v4 的全部机制：差异锚定、连接图补全、SQLite 值域、隔离与受控增长、变异搜索。在此基础上增加：
- **取值池过滤与扩充**：取值池先按 R 层约束过滤，再补充观测真实值。"满足某条查询谓词"的候选也会从真实值中搜索。
- **真实行模板**：每张表预先抽取 60 行官方真实行。查询不涉及的列直接取自模板，因此整行在现实中是一致的。
- **键值**：数值键用新标识；文本键用尚未使用过的真实值；字典表的键只取官方键。
- **R 层修复**：
  - 字典表的行替换为官方行，必要时重映射键；
  - 唯一列组合冲突时，改写非关键列，改不动则删行；
  - 补足未声明外键对应的父行；
  - 补足完全参与所需的子行，并优先复用已有父行；
  - 补对称行、删除自环；
  - 修正年份与日期的一致。
- **接受条件**：认证器在环，同时要求 L1f 与 R 层全部约束。

### 基线：信息与预算完全对等
- **随机模糊-R（fuzz_r）**：每行从官方真实行出发，查询涉及的列从字面量、观测值或 NULL 中随机抽取，键取三值小域，使连接能够发生。使用同一套 DDL 与 R 层修复，接受条件为 L1f 加 R 层，与认证器在环一致。不使用连接图、锚定、隔离或增长算子。
- **ParSEval-R**：生成器为官方原版，取值器优先给出观测真实值，接受条件为 L1f 加 R 层，并反复换种子直到预算用完。
- **已有结果的复认证**：已有结果（v4 各方法、SpotIt、SpotIt+）均按 R 层重新认证，记入 `cert_R` 字段，不改动原有 `cert`。

## 3. 开发与冻结

- R 层方法只在**开发集**上调试，用开发集的 EX 判对对和已知阳性对；不看任何测试集的 R 层结果。
- 调试结束后记录 SHA256，写入 `docs/FREEZE_R.md`，然后在测试集上**一次性**运行：
  - CGX-R、fuzz-R、ParSEval-R：在全部 6,456 个不同 EX 判对对上运行，每对 5 s；
  - CGX-R、fuzz-R：在已知阳性对上运行。

## 4. 假设与判定（测试集）

- **H5（机械终点）**：在 EX 判对对上，CGX-R 的 R 层认证见证数大于 fuzz-R，也大于 ParSEval-R。采用配对 McNemar 精确检验，并以题目为单位做聚类 bootstrap 求 95% CI，Holm 校正。
- **H6（语义终点）**：从 CGX-R、fuzz-R、ParSEval-R 的 R 层见证中，各随机抽取 100 个不同的对做盲标。盲标统一流程（第 5 节）。用"有意义比例 × 见证数"估计有意义见证数，CGX-R 的估计值应大于每个基线；差值的 95% CI 用参数 bootstrap 求得，即对两个方法的比例做二项重抽样。
- **H7（现实性改进）**：CGX-R 见证中被判为 implausible_data 的比例低于 v4 在 L1f 层的同一比例。后者由 06 号文档中的两遍标注给出，正式版将按统一流程重标。检验采用两比例检验。
- **次要指标**：已知阳性召回率（R 层）；按系统统计的 EX 修正与排名；归因中的 pred_wrong 与 gold_wrong 构成；基准标注问题清单（gold_wrong）。
- **允许阴性结果**：若 H5–H7 不成立，照实报告。

## 5. 归因标注统一流程

- 每个方法随机抽取 100 个不同的对（种子固定）。标注时隐藏方法名；每批由两个独立子代理分别标注，都使用同一份说明。
- 标注者可以对官方库执行只读 SQL，用来核实"某种数据在现实中是否出现"。这条要求对所有批次一致，包括重标 v4、SpotIt、ParSEval 与 fuzz 的批次。
- 两遍不一致的条目由第三遍裁决。报告两遍之间的一致率和 κ。
- 作者对 30 条做人工抽查，抽查表为 `results/test/audit/human_check.md`。论文中报告作者与 AI 判定的一致率。
- 论文中写明：归因判定由 AI 辅助完成，并经作者抽查。
