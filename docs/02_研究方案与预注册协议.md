# 02 研究方案与预注册评测协议（CGX-Protocol v1）

日期：2026-10-13　　状态：**预注册版本，冻结于测试集运行之前**（冻结 git hash 记录在 `docs/FREEZE.md`，测试集只运行一次）

---

## 0. 研究问题

Text-to-SQL 系统通常用"执行准确率"（EX：在一个官方数据库上比较预测 SQL 与 gold SQL 的结果集合）评分。两条不等价的 SQL 可能恰好在这个库上结果相同，于是 EX 高估准确率。已有补救工具：

* **SpotIt / SpotIt+**（ICLR 2026；arXiv 2603.04334）——有界形式化验证（扩展 VeriEQL），SpotIt+ 再加挖掘到的现实性约束；
* **ParSEval**——覆盖导向的符号测试数据库生成；
* **Test-suite accuracy**（Zhong et al., EMNLP 2020）——随机/蒸馏数据库套件；
* **XData / EvoSQL**——针对 SQL 变异体或覆盖目标的测试数据生成。

**RQ1（方法）**：一种只依赖 DDL、执行在真实 SQLite 语义上的"差异锚定 + 掩蔽隔离 + 连接图补全"见证合成方法（CGX），能否在**同一认证器、同一比较契约、同一现实性门槛**下，比上述基线证伪更多"EX 判对但实际不等价"的预测？
**RQ2（协议）**：现有评测器的结论对**比较契约**与**见证现实性门槛**有多敏感？
**RQ3（知识）**：EX 漏判的不等价有哪些可迁移的 SQL 语义成因（掩蔽、LIMIT 平局、整数除法、空聚合、NULL、类型亲和、JOIN 重复……），在 10 个模型、11 个 schema 上的分布如何？对模型排名有何影响？

## 1. 数据与划分（已由 `src/build_dataset.py` 确定性生成）

* 题目：BIRD dev（2024-06-27 修订版）1534 题，11 个 schema；DDL 来自 ParSEval 官方产物中的原始 `CREATE TABLE`。
* 预测来源：SpotIt+ 仓库公开的 10 个方法预测（alpha、chess、csc-7b、csc-32b、gena_submission_1/2、gsr、omni-32-majority、rsl、slm）；ParSEval 产物中的第 11 套预测（旧版 gold，此前已暴露）只用于开发。
* EX 标签：SpotIt+ 作者在官方 BIRD 数据库上计算并公开的逐题 EX（本沙箱无法下载官方库，如实注明）。
* **划分（预注册，盐值固定）**：
  * 留出 schema：`sha256("cgx-holdout-schema-v1|"+schema)` 最小的 3 个 → **superhero、toxicology、formula_1** 全部进测试集；
  * 其余 8 个 schema 按 (schema, 难度) 分层，`sha256("cgx-question-split-v1|schema|qid")` 排序，前 30% 进开发集；
  * 此前团队暴露过的 43 题：在非留出 schema 中强制进开发集；在留出 schema 中排除（11 题，不参与任何评估）。
  * 结果：开发 349 题、测试 1174 题、排除 11 题；测试对 11,740 个（其中 EX-correct 7,995 个）。
* 开发期间**只允许查看开发集题目**；测试集仅在冻结后一次性运行。

## 2. 评估总体

* **P_EXC**（主总体）：测试集中 EX = correct 的 (题, 模型) 对。真值未知；目标是证伪。
* **P_EXI**（已知阳性）：测试集中 EX = incorrect 的对。官方数据库已经区分了两条查询，因此它们**在集合契约下必不等价**——用来测量各工具的**召回率**，无需人工标签。
* **去重口径**：同一题下规范化后相同的预测 SQL 视为同一"不同对"；主表报告原始对，附表报告去重后结果。

## 3. 认证器（所有方法共用、独立实现）

一个声称"不等价"的见证数据库 W 被**认证**，当且仅当：
1. 在全新的内存 SQLite 中执行**原始** DDL（不改写大小写、标识符或字面量），`PRAGMA foreign_keys=ON`，W 的所有插入成功（PK、NOT NULL、UNIQUE、FK 均满足）；
2. 原始 gold SQL 与原始预测 SQL 在 W 上都执行成功（任一方报错不计为见证）；
3. 在所选**比较契约**下结果不同。

比较契约（全部报告，**主契约 = C_set**）：
* **C_set**：BIRD 官方 EX 的定义，`set(rows_pred) == set(rows_gold)`；
* **C_bag**：多重集合相等（忽略顺序，保留重复）；
* **C_lenient**：在 C_set 基础上把"空结果"与"单行全 NULL"视为相等，数值按 1e-9 相对误差比较（用于检验结论是否依赖边角语义）。

## 4. 见证现实性分级

* **L0**：认证通过（满足 DDL 声明的全部约束）。
* **L1**：L0 + 类型忠实（INTEGER/REAL 列只存数值，TEXT 列只存文本，DATE/DATETIME 列为可被 `date()`/`datetime()` 解析的 ISO 文本）+ 两条查询引用到的每张表至少 1 行。
* **L2**：L1 + 满足 SpotIt+ 作者为该库挖掘并经 LLM 校验的现实性约束（range、categorical、not-null、函数依赖；直接读取其公开 JSON）。用**对手自己的约束**检查所有方法的见证。
* **主终点采用 L1**；L0、L2 同表并列报告。

## 5. 比较方法

| 方法 | 运行方式 | 预算 |
|---|---|---|
| **CGX（本文）** | 冻结版本，同机重跑 | 每对 10 s 墙钟、单核 |
| CGX + SC | CGX 在生成时额外遵守 SpotIt+ 约束（与 SpotIt+ 同条件比较） | 同上 |
| SpotIt（vanilla） | 采用作者公开的逐题结果与反例；其反例经列名映射后再用本认证器复核；报告"作者自报"与"本认证器复核"两种口径 | 作者设置（单题累计可达数百秒，bound 1–5）——**对基线让分** |
| SpotIt+（LLM 约束） | 同上，采用作者公开结果 | 同上 |
| ParSEval | 固定 commit，同机重跑，其生成的数据库交本认证器 | 每对 10 s |
| 随机模糊（Test-suite 式） | DDL 合法随机库，值域取自两条查询的字面量与类型随机值，FK 一致 | 每对 10 s |
| EX | 官方数据库（作者公开结果） | — |

## 6. 假设与判定标准

* **H1**：在 P_EXC 上，CGX 的 L1 / C_set 认证见证数 > SpotIt（作者自报口径）。
* **H2**：在 P_EXC 上，CGX+SC 的 L2 / C_set 认证见证数 > SpotIt+（作者自报口径）。
* **H3**：在 P_EXI 上，CGX 的召回率 > SpotIt 与 ParSEval。
* **H4（消融）**：去掉"差异锚定""掩蔽隔离""连接图补全""SQLite 值域"任一组件，P_EXC 见证数显著下降。
* 统计：配对 McNemar 精确检验（逐对是否找到见证）；以**题目为聚类单位**的 bootstrap 95% CI（10,000 次）；H1–H3 用 Holm 校正，α = 0.05。
* **假阳性**：任何方法"声称不等价但认证失败"的数目单独报告；CGX 的设计目标为 0。
* **允许阴性结果**：若 H1/H2 不成立，照实报告，论文重心转为协议与 RQ2/RQ3，不追加选择性实验。

## 7. 次要分析

* 每个模型的"修正准确率" = EX-correct 中未被任何方法证伪的比例（上界），及 Kendall τ 排名变化；
* 成因分类：对每个认证见证自动标注差异锚点类别，并人工抽检 100 个核对标注准确率；
* **残差审计**：P_EXC 中无人能证伪的对，按模型分层随机抽 100 个，逐一人工（AI 辅助，注明）判定是否真等价，估计各工具假 EQ 率及其 Wilson CI；
* 成本：每对时间分布（中位、p95）、超时、错误、不支持比例。

* 所有分母保留：错误、超时、不支持、认证失败一律计入。
